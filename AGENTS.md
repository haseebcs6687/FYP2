# AGENTS.md — EduGen Multi-Agent Architecture (FYP-2)

## Project purpose
EduGen teaches and assesses Java / object-oriented programming through four
collaborating autonomous agents. Adaptivity operates at **concept** level
(44 canonical tags), not topic level, and all content is generated at request
time and grounded in a retrieval index.

---

## Agent roles
> Do not deviate from these roles without explicit instruction.

**1. Coordinator** — `agents/coordinator_agent.py`
Central router. Pure control flow: no pedagogy, no analysis, no LLM calls.
- First visit (no quiz history) → Concept Clarifier directly
- Returning student → Performance Analysis → Adaptive Content → Concept Clarifier
Emits a `trace` consumed by `/pipeline`.

**2. Performance Analysis** — `agents/performance_analysis_agent.py`
Measures mastery per concept. Identifies weakness strictly; never decides what
to do about it. Signals: accuracy, recency-weighted mastery (EWMA), trend,
response time, repeated distractor choice, prerequisite position, review decay.

**3. Adaptive Content** — `agents/adaptive_content_agent.py`
Deterministic 6-rule policy engine (R1–R6). Outputs the target concept,
difficulty, action, human-readable reasoning, machine-readable evidence, and
the **retrieval brief**. The student may accept or override; both are recorded.

**4. Concept Clarifier** — `agents/concept_clarifier_agent.py`
The only agent permitted to make external LLM calls. Retrieves passages against
the brief, assembles a grounded prompt, validates the JSON response, and forces
all tags back into the 44-tag canonical vocabulary.

## Current state
- **Backend:** Flask application factory in `app.py`, blueprints in `routes/`
- **Database:** SQLite at `data/edugen.db` — `users`, `students`, `quiz_results`,
  `question_attempts`, `quiz_sessions`, `recommendations`, `lesson_views`
- **RAG:** file-backed hybrid index at `data/rag_index/`, built by
  `python -m rag.ingest` from `rag/corpus/`
- **Auth:** server-side sessions; `student_id` is never accepted from the client
- **Frontend:** 12 server-rendered Jinja2 pages, vanilla JS, no framework
- **Agent log:** `core/agent_log.py` + `/api/logs` polling, rendered by the
  floating console. Must be preserved and extended for new agent actions.

---

## Conventions
- Python + Flask; vanilla HTML/JS/CSS on the frontend
- One agent per module in `agents/`, with a documented input and output shape
- All concept vocabulary comes from `core/concepts.py` — never hard-code tags
- Thresholds live as named constants at the top of their agent file
- Every agent action calls `add_log` so the console reflects reality

## Known limitations
1. Generated question correctness is structurally validated, not
   semantically verified. Manual sampling is required for the report.
2. SQLite suits a single-user demo, not concurrent classroom deployment.
3. Policy rules are hand-tuned rather than learned — a deliberate trade for
   explainability.
4. Response time alone cannot distinguish deep thought from walking away.
