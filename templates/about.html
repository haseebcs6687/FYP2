How EduGen works

The architecture, written for someone evaluating the project rather than using it.

The pipeline

One student request passes through four agents. Each has one job and a documented input and output, so any of them can be replaced without touching the others.

Coordinator

Routing and orchestration
in: student id · out: pipeline route + trace
→

Performance Analysis

Measures mastery per concept
in: question attempts · out: weakness report
→

Adaptive Content

Chooses concept and difficulty
in: weakness report · out: decision + retrieval brief
→

Concept Clarifier

Retrieves sources, generates content
in: retrieval brief · out: lesson or quiz + citations

Why concept-level instead of topic-level

"Inheritance" is not one skill. A student can understand extends perfectly and still fail every question about super(). EduGen models {{ concept_count }} concepts across 8 modules, tags every question with the concepts it tests, and scores each concept separately.

Why a prerequisite graph

The concepts are connected by dependency edges. When a student fails method-overriding, the Performance Analysis Agent checks its prerequisites; if inheritance-basics is also shaky, the Adaptive Content Agent teaches the prerequisite instead. Treating the cause beats repeating the symptom.

Signals beyond right and wrong

  • Recency-weighted mastery — an EWMA so improvement is visible immediately
  • Trend — improving, declining or steady across the attempt history
  • Response time — correct but slow is flagged as fragile knowledge
  • Distractor analysis — a repeated wrong option is a named misconception, and it is fed into the next prompt
  • Review decay — mastered concepts become due again after a week

Retrieval-augmented generation

The Adaptive Content Agent does not send a vague instruction. It writes a retrieval brief: concept, difficulty, query terms, tag filter and the student's own misconceptions. The Concept Clarifier runs that against a hybrid index (vector similarity + lexical overlap + concept-tag match) and grounds the generated lesson in the passages it gets back, citing each one.

Student agency

Every recommendation shows the rule that fired and the evidence. The student can accept it or pick something else, and both are recorded. The acceptance rate is reported on the history page, which turns "did students trust the agent" into a measurable result.

Security

The student identity comes from a signed server-side session, never from the request. There is no endpoint where changing a number in the URL exposes another student's record. Passwords are stored as PBKDF2 hashes.

Stack

Python 3.10+ · Flask · SQLite · server-rendered Jinja2 with vanilla JavaScript · a file-backed vector store built on NumPy · sentence-transformers, Ollama or a dependency-free hashing embedder · an OpenAI-compatible LLM endpoint for generation.
